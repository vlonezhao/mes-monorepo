# MES 系统架构说明（MVP）

## 技术栈

| 层级 | 技术选型 |
|------|----------|
| 前端 | Vue 3 |
| 后端 | NestJS |
| 数据库 | PostgreSQL |
| 缓存 | Redis |
| 构建 / 编排 | Turbo |

## Monorepo 结构

```
mes-monorepo/
├── apps/
│   ├── web/          # Vue3 前端应用
│   └── api/          # NestJS 后端应用
├── packages/
│   └── shared/       # 共享类型、枚举、常量
└── docs/             # 项目文档
```

## 前后端架构

### 后端（NestJS）

- 按业务模块划分 NestJS Module，与 PRD 中 P0–M7 模块一一对应
- 统一全局能力：模块化注册、全局异常处理、请求校验、Swagger API 文档
- 数据库迁移体系（TypeORM 或 Prisma）支撑 schema 演进
- 报工、库存扣减等并发场景使用乐观锁或数据库行锁，防止重复报工

### 前端（Vue 3）

- 按业务模块划分路由域，与后端模块对齐
- 状态管理：Pinia
- HTTP 层：Axios 封装，统一鉴权与错误处理
- 布局框架 + 统一 UI 规范
- 车间执行页面面向现场操作优化：大按钮、少输入

### 前后端协作

- `packages/shared` 承载跨端共享的 DTO、枚举、类型定义，保证契约一致
- API 通过 Swagger 文档化，前后端按模块契约并行开发

## Redis 与数据库职责

### PostgreSQL

- 持久化全部业务数据（主数据、工单、报工、质检、物料、追溯等）
- 按模块分 schema 或表前缀组织
- 关键业务表统一包含 `created_at`、`updated_at`、`created_by` 审计字段

### Redis

| 用途 | 说明 |
|------|------|
| 会话管理 | JWT + Refresh Token 会话状态 |
| Token 黑名单 | 登出后 Token 失效 |
| 字典缓存 | 数据字典等低频变更、高频读取数据 |
| 看板聚合缓存 | 生产概览等统计结果，TTL 30s–5min |

## 模块划分原则

1. **业务对齐：** 每个 PRD 业务模块（P0–M7）对应一个后端 NestJS Module 和一个前端路由域
2. **依赖单向：** 模块间依赖遵循 PRD 模块依赖图，下层模块不反向依赖上层
3. **共享下沉：** 跨模块共用的类型、枚举、常量放入 `packages/shared`，避免前后端重复定义
4. **数据归属清晰：** 每个模块拥有其核心实体表，跨模块引用通过 ID 关联，不跨模块直接操作对方数据
5. **平台先行：** P0 平台基础模块为所有业务模块提供认证、权限、字典等公共能力，业务模块不重复实现
6. **MVP 克制：** 架构按 MVP 范围设计，不为 V2+ 能力（APS、WMS、IoT 等）预留过度抽象
