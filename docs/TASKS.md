# MES 系统开发任务（MVP）

> 估算基准：2 人全栈团队，约 10–12 周。按依赖关系递进，每阶段结束应有可演示增量。

## 阶段划分

| 阶段 | 名称 | 周期 | 目标 |
|------|------|------|------|
| 阶段 0 | 工程基建 | 第 1–2 周 | Monorepo 可运行，前后端联调通畅 |
| 阶段 1 | 平台 + 主数据 | 第 3–4 周 | 能维护完整生产主数据 |
| 阶段 2 | 工单 + 车间执行 | 第 5–7 周 | 跑通生产执行主链路 |
| 阶段 3 | 物料 + 质量 + 追溯 | 第 8–9 周 | 补齐制造闭环的数据完整性 |
| 阶段 4 | 看板报表 + 打磨 | 第 10–12 周 | MVP 可对外演示 |

## 开发顺序

### 阶段 0：工程基建

| 顺序 | 任务 | 产出 |
|------|------|------|
| 0.1 | Turbo Monorepo 脚手架（`apps/web`、`apps/api`、`packages/shared`） | 项目骨架 |
| 0.2 | NestJS 基础：模块化、全局异常、校验、Swagger | API 框架 |
| 0.3 | PostgreSQL + ORM 迁移体系 | 数据库基建 |
| 0.4 | Redis 接入（会话、缓存） | 缓存层 |
| 0.5 | Vue3 基础：路由、Pinia、Axios 封装、布局框架 | 前端框架 |
| 0.6 | CI 基础（lint、build、test） | 质量门禁 |

### 阶段 1：平台 + 主数据

| 顺序 | 模块 | 功能范围 |
|------|------|----------|
| 1.1 | P0 | 登录、RBAC、用户管理、数据字典 |
| 1.2 | M1 | 物料、产品 |
| 1.3 | M1 | BOM（单层） |
| 1.4 | M1 | 工艺路线、工序、工位 |

### 阶段 2：工单 + 车间执行

| 顺序 | 模块 | 功能范围 |
|------|------|----------|
| 2.1 | M2 | 工单创建、列表、下达 |
| 2.2 | M2 | 工序任务自动生成、状态机 |
| 2.3 | M3 | 待办列表、开工、报工、完工 |
| 2.4 | M3 | 报工业务规则校验 |
| 2.5 | M2 | 工单完工关闭 |

### 阶段 3：物料 + 质量 + 追溯

| 顺序 | 模块 | 功能范围 |
|------|------|----------|
| 3.1 | M4 | 工单领料、批次绑定 |
| 3.2 | M4 | 消耗登记、逻辑库存 |
| 3.3 | M5 | 必检工序质检、不良原因 |
| 3.4 | M6 | 成品批次、正向 / 反向追溯 |

### 阶段 4：看板报表 + 打磨

| 顺序 | 模块 | 功能范围 |
|------|------|----------|
| 4.1 | M7 | 生产概览看板、工单进度 |
| 4.2 | M7 | 产量统计、不良率报表 |
| 4.3 | P0 | 操作审计日志完善 |
| 4.4 | 全模块 | 权限细调、边界 case 修复 |
| 4.5 | 全模块 | 种子数据 + 演示脚本 |

## 里程碑

| 阶段 | 里程碑 | 验收要点 |
|------|--------|----------|
| 阶段 0 | 工程可运行 | 健康检查接口 + 登录页空白壳可访问 |
| 阶段 1 | 主数据就绪 | 计划员可录入「产品 A = BOM + 3 道工序」完整主数据 |
| 阶段 2 | 执行闭环 | 操作工完成一张工单全流程报工，系统状态正确流转 |
| 阶段 3 | 追溯可用 | 输入原料批次，可追溯到成品批次及完整工序记录 |
| 阶段 4 | MVP 可演示 | 完整 Demo：主数据录入 → 工单完工 → 追溯查询 → 看板展示 |
